# 外部 RDP 兼容方式

核对日期：2026-10-30。兼容策略是“普通桌面连接先尝试 PureRDP，首次连接失败再切换系统 MSTSC”。不将离线验证等同于全部厂商现场认证通过。

## 使用方式

每次外部 `.rdp` / MSTSC 代理请求创建独立的 PureRDP 连接窗口。即使堡垒机地址、端口和账号相同，也不复用、断开或重新配置旧的外部会话。外部请求不接管设备库预览；关闭其中一个窗口不影响其他窗口。设备库连接保持原有复用规则。

默认先尝试 PureRDP，无需关闭 MSTSC 启动代理。普通未知字段、空字段、默认性能选项、重复键和未填写用户名不会提前切换原生。NSFOCUS 路由票据、ORAssistant 临时加密密码及 H3C 远端启动信息继续优先在 PureRDP 内打开。

外部连接首次建立失败时，关闭失败的内嵌窗口，再尝试一次原生客户端；成功登录、手动取消、正常关闭和主机关机不会触发切换。远端正在显示登录页、等待用户输入密码，并不等于建立连接失败，不使用任意超时强制切换。

实际启用的网关、RemoteApp、多显示器、云身份认证、签名或预连接数据等不能等价实现的功能仍直接使用原生，保留必要语义。未知 MSTSC 命令参数也交由原生识别，不将安全选项降级为普通连接。

在“全局设置 → .rdp 代理”勾选“外部连接始终使用原生 MSTSC（优先兼容）”并保存，可让助手的外部连接始终走系统客户端。适用于依赖原生窗口代填或其他专属流程的场景。设备库内保存的连接继续使用 PureRDP。

原生连接使用自己的窗口、快捷键、缩放、确认提示和重连行为；PureRDP 的控制栏与外部通用设置只适用于内嵌连接。不会为了套用通用设置改写带签名或临时票据的原文件。

## MSTSC 参数核对

以下以 [微软 MSTSC 命令说明](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/mstsc) 为基准。Windows 版本、系统策略和远端支持仍由原生客户端判断。

| 参数 | 路径 |
| --- | --- |
| 普通连接文件、`/v`、`/admin`、`/f` 或 `/fullscreen`、`/w`、`/h` | 优先内嵌，首次失败后原生；明确需要原生能力的功能例外 |
| `/g`、`/public`、`/span`、`/multimon`、`/l` | 原生兼容 |
| `/restrictedAdmin`、`/remoteGuard` | 原生兼容，不转换成普通密码登录 |
| `/prompt` | 优先内嵌，失败后原生兼容 |
| `/edit`、`/?` | 原生兼容，保留原生编辑和帮助行为 |
| `/shadow`、`/control`、`/noConsentPrompt` | 原生兼容，保留系统策略和权限检查 |
| 其他参数 | 原样交给 MSTSC 自行识别或报错，不静默删除，不通过命令解释器执行 |

`/public` 等安全参数一旦存在，整个启动请求使用原生客户端，不与内嵌设置混合。

## 文件字段

显示兼容与清晰度：动态助手连接首次按实际窗口客户区像素申请桌面，避免将旧文件中的较小尺寸直接放大。固定分辨率模式仍尊重文件宽高；连接后保留旧堡垒机不反复请求尺寸的防闪烁处理。实际画面与显示区域一致时关闭 SmartSizing，尺寸不一致时仅进行必要的完整画面适配。推荐配置见 [中文说明](../README.zh-CN.md#显示清晰度与推荐配置)。

内嵌连接读取目标、用户名和域、显示尺寸、压缩与缓存、本地资源重定向、键盘、CredSSP、证书验证、协商、管理会话和提示凭据等已有映射。另有以下只驻留本次连接内存的字段：

- `password 51:b:`：同一电脑、同一 Windows 用户的 DPAPI 解密；不导出为设备密码。
- `loadbalanceinfo:s:`：按 ActiveX 的二进制 BSTR 规则传入路由票据。
- `alternate shell:s:`、`shell working directory:s:`：传入远端启动程序和目录，不在本地执行。

未知字段不再一律触发原生打开；PureRDP 先使用已支持字段尝试连接，未知字段的具体功能不宣称已在内嵌控件实现。带签名、活动网关等明确需要原生能力的文件仍直接交给 MSTSC。需要厂商代填的场景可显式开启“始终使用原生”。

[微软 RDP 字段说明](https://learn.microsoft.com/en-us/azure/virtual-desktop/rdp-properties) 按产品分别列出适用范围；出现于某个云客户端的字段，并不表示当前机器的 MSTSC 或 ActiveX 必然支持。

## 原生启动与凭据保护

仅运行 Windows 系统目录中的 MSTSC。直接原生连接保留原文件与参数；失败后切换保留原始文件字节和显式的目标、尺寸、全屏、管理会话及凭据提示参数。原生启动先创建并立即解除调试关系后恢复运行，以避开本应用 IFEO 代理的递归；不临时修改全局代理、不替换系统文件、不注入代码或输入、不读取进程内存。

为防止助手提前删除连接文件，导入时在内存保留最多 1 MiB 的原始字节，仅在实际失败切换时写入当前用户 TEMP 下的独立随机目录，原生连接结束后删除。成功登录或取消时清空内存副本；不写入设备库、通用设置或 JSON，也不将密码解密后落盘。原始助手文件不改写。用户另行修改目标、账号或密码后取消原请求的自动切换，避免使用旧身份重试。

启动助手进程保持到原生连接结束，减少助手在子进程提前退出时删除临时文件的问题。防递归标记只写入该子进程环境。若企业策略阻止兼容启动，显示失败提示，仍可使用现有“关闭并恢复”。

## 验证与边界

离线回归覆盖参数分流、未知/签名/重复字段、原文件不变、参数逐项往返、解除调试、退出码和环境隔离；使用隔离桌面中的自有合成子程序，并实际打开系统 MSTSC 的 `/?` 帮助页后仅关闭该测试进程的窗口。不指定远程主机、不使用真实账号或远程会话、不更改系统 IFEO。本机帮助页关闭返回码为 1，合成子程序的退出码则逐值核对。

NSFOCUS 路由票据、ORAssistant 临时加密密码、H3C AccessClient 远端启动字段已经有对应导入回归。各现场的最终登录仍需实际新会话验收。尤其是厂商绑定原始进程句柄、进程关系、插件或安全策略的流程，即使交给原生 MSTSC，也不能仅凭参数完整就保证等价；可关闭启动代理保留厂商原链路。
