## 项目介绍

PureRDP 是面向 Windows 的远程桌面连接管理工具，适合需要经常访问多台电脑、服务器或运维设备的场景。项目以微软原生 RDP ActiveX 为连接核心，在此基础上提供设备库、多窗口管理、远程画面预览、状态观察和统一设置，减少重复填写连接信息与来回寻找连接窗口的操作。

## 主要功能

- **快速迁移原生 RDP 历史**：新建设备时自动读取当前 Windows 用户的远程桌面地址历史，合并到地址下拉框并去重；选择地址后仍需主动保存。不导入密码，也不修改系统历史。

  选中原生历史地址后自动填入已保存 Windows 凭据的用户名；没有保存凭据则使用原生历史的用户名提示。连接复用 Windows 中该目标已有的凭据，密码不明文回显、不复制到设备配置；只有用户名提示而未保存密码时，仍需输入密码。

- 设备集中管理：支持设备名称、标记颜色、IP/域名和自定义端口，提供卡片、横排、列表视图，以及搜索、拖动排序、编辑和删除。
- 多连接窗口：支持多台设备同时连接，可选独立窗口或自动宫格布局，并提供连接切换、最大化、真全屏、批量最小化与原状态恢复等控制。
- 远程画面预览：设备卡片可显示只读预览；已有连接时复用会话，没有连接时可单独建立预览会话。
- 显示与缩放：支持动态分辨率、画面拉伸、默认画面缩放、宫格缩放和 DPI 设置，可按设备保存。
- 状态与日志：按配置周期检查 TCP 地址和端口，显示连接质量、带宽、延迟及探测丢包率；提供手动刷新和连接次数、时长、起止时间统计。
- 控制栏与快捷键：控制栏可置于窗口上下左右并居中，可选自动隐藏；PureRDP 快捷键支持自定义及冲突检查，普通 Windows 组合键按设备和窗口状态选择本地或远端处理。
- 本地资源重定向：可配置剪贴板、磁盘、打印机、智能卡、声音、麦克风和摄像头；实际可用性取决于服务端策略、驱动与远端应用。
- 连接重试：断线后采用递增间隔重试，最多 10 次；取消会关闭当前连接。控件明确报告远端关机时，不再自动重连。
- 配置与启动：支持标准 `.rdp` 文件、命令行入口、全局 JSON 设置导入/导出、系统托盘、单实例唤醒、登录 Windows 后自启动和静默启动。
- 数据位置说明：全局设置提供“数据与清理”页，可查看数据目录和日志位置、打开目录或复制路径，不自动删除数据。

## 项目优点

- 连接入口集中：把设备信息、连接操作、预览和状态放在同一控制台，减少重复输入与窗口查找。
- 适合多设备操作：独立窗口与宫格布局兼顾单台精细操作和多台并行查看，设备颜色与名称便于区分目标。
- 保留原生连接核心：使用 Windows RDP ActiveX，不另外实现 RDP 协议栈；认证和资源重定向由系统控件与服务端协商。
- 配置粒度清楚：设备设置与全局偏好分开，显示模式、键盘转发和本地资源可按设备配置，控制台偏好统一管理。
- 便于搬移与交付：当前采用免安装、不带运行时的单文件程序和普通文件夹交付；源码附同次编译程序，目标电脑仍需 .NET 10 Desktop Runtime x64。
- 数据可查、维护方便：配置与日志保存在本机，密码使用 Windows 凭据管理器，数据位置和清理注意事项可在设置中查看；源码保留构建脚本和回归检查，便于维护。

以上为现有功能与设计特点，不代表在所有 Windows、网络或远端策略下都具有相同兼容性，也不承诺比 `mstsc.exe` 更低的 CPU/内存占用或完全无闪烁。

## 直接运行

版本：2.0.0；文档更新：2026-10-13。

双击 `PureRDP.exe`，无需安装 MSI。当前默认仅发布 Windows x64 不带运行时单文件版，需要安装 .NET 10 Desktop Runtime x64。

- 发布文件夹：`D:\Agant\Github_Releases\PureRDP\`（不压缩，只保留最新版）。
- 源码文件夹：`D:\Agant\Github_Source\PureRDP\`（不压缩，只保留最新版），内附同次编译的不带运行时可执行文件。
- 构建暂存：`outputs/2.0.0-independent-preview/`。不再主动生成自带运行时版本，历史包不自动删除。

程序依赖 Windows 的远程桌面 ActiveX 控件。“不带运行时”不等于“不需要运行时”。源码文件夹内附有 `outputs/2.0.0-independent-preview/PureRDP.exe` 及说明文件。

这是免安装单文件应用。连接历史与窗口设置仍按上游逻辑存入用户配置目录，保存的密码使用 Windows 凭据管理器。它不是“完全不向系统写入数据”的沙盒应用。

## 设备库前端

首页采用三种设备视图：卡片、横排和列表。支持实时搜索、单击卡片直接连接、编辑、删除、拖动排序、键盘 Enter/Space 连接，以及自动保存视图和顺序。主界面使用不透明的高对比按钮；半透明流动玻璃控制条仅在 RDP 连接窗口启用，避免首页按钮与背景混淆。

设备状态圆点表示 TCP 地址和端口的可达性，不代表账号已通过认证或 RDP 登录成功。连接质量、延迟和丢包属于采样结果，实际可用性仍需结合远程操作与服务端状态判断。

## 快捷键默认值

| 功能 | 默认快捷键 | 再次按下 |
| --- | --- | --- |
| 置前/最小化连接 | Ctrl+Alt+Z | 最小化或原样恢复全部连接窗口；没有连接窗口时不处理。后台预览不计入连接窗口 |
| 最大化/还原窗口 | Alt+X | 切换窗口状态 |
| 打开控制台 | Alt+W | 返回原连接；无连接时显示/隐藏控制台 |
| 真全屏 | Alt+V | 切换真全屏状态 |
| 循环切换连接窗口 | Alt+N | 切换下一个连接 |
| 关闭连接窗口 | Alt+M | 关闭当前连接 |

可在“全局设置 → 快捷键”捕捉新组合，Esc 或 Backspace 清空。系统注册检测不能识别所有其他软件自定义键盘钩子的冲突。自动检测及编译检查不等同于全部远程桌面环境的实测。

快捷键页中的“同步连接窗口”会让 PureRDP 控制快捷键跟随当前连接的键盘模式；“始终本地生效”会优先在本机处理这些 PureRDP 控制快捷键。普通 Windows/RDP 按键不属于 PureRDP 快捷键，始终遵循当前设备的键盘模式。

## 设置保存与自启动

- 设备连接文件通常位于 `%APPDATA%\PureRDP\Recent\`，格式为 `.rdp`。无法写入时依次尝试本地应用数据目录、程序目录下的数据目录和临时目录。
- 全局设置位于 `%APPDATA%\PureRDP\global-settings.json`；设备列表布局通常位于 `%APPDATA%\PureRDP\connection-library.json`。
- 密码由 Windows 凭据管理器保存，不写入连接配置明文。
- 开机自启动针对当前 Windows 用户登录，通过 `HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Run` 下的 `PureRDP` 项登记。
- 移动 EXE 后，在新位置运行程序，再点击“修复路径”。取消自启动并保存会删除此启动项。
- 自启动路径属于本机配置，不随全局 JSON 导入或导出。修改设备设置后点击保存，后续连接和重启将从保存的文件读取。

## 外设使用

1. 填写计算机地址和用户名。
2. 在“本地资源与设备”中开启“双向剪贴板同步”和“使用本地打印机”。
3. 麦克风选择“使用本地麦克风”；摄像头填 `*`。
4. 如需磁盘，填 `C;E` 等盘符或 `*`。GUI 会保留你的选择。
5. 连接后在远端目标应用中验证摄像头、录音和实际打印。服务端策略、设备驱动和应用兼容性仍决定最终可用性。

“动态分辨率”会改变远端实际桌面尺寸；“拉伸画面”仅缩放图像。两者互斥。当前没有新增任意 FPS 滑块。

## 从源码生成 EXE

GitHub Actions 使用 .NET 10，构建与发布均开启分析器。WinForms 设计器属性序列化检查（WFO1000）和编译器问题会阻断构建；第三方 IDISP 资源所有权提示仍输出为警告，需人工审查。CI 使用 runner 临时目录缓存 NuGet 包，运行 `Build/scripts/purerdp.test.ps1` 执行 7 组离线回归，报告位于 `outputs/ci-tests/TestResults/`。发布工作流从 Release 标签的源码构建，只上传不带运行时的 EXE 和说明文件。

需要 Windows、.NET 10 SDK 和 PowerShell。首次构建先恢复依赖，再编译应用项目：

```powershell
. ./Build/scripts/_nuget-cache.ps1
dotnet restore PureRDP/PureRDP.csproj -r win-x64
dotnet build PureRDP/PureRDP.csproj -c Release
./Build/scripts/purerdp.publish-portable-zh.ps1
```

发布脚本可通过 `-Dotnet` 指定本地 SDK 的 dotnet.exe，默认优先使用 `D:\Agant\toolchain\dotnet\dotnet.exe`。构建与发布脚本统一使用 `D:\Agant\toolchain\nuget\packages` 存放 NuGet 缓存，不再在项目内创建 `.nuget`。直接运行 dotnet 命令时，先执行 `. ./Build/scripts/_nuget-cache.ps1`。发布脚本会先恢复依赖并刷新缓存路径，再以 `--no-restore` 发布。默认只生成 Windows x64 不带运行时的单文件程序，不构建安装器，不生成压缩包或带运行时版本。

- 运行版：`D:\Agant\Github_Releases\PureRDP\`。
- 源码：`D:\Agant\Github_Source\PureRDP\`，内附 `outputs/2.0.0-independent-preview/PureRDP.exe`。
- `-ReleaseDirectory` 和 `-SourceDirectory` 可修改输出父目录，其下统一使用 `PureRDP` 名称。替换前校验文件哈希，历史输出移到项目内可恢复备份；被运行中的程序占用时不会强行关闭进程。

也可仅生成不带运行时的可执行文件：

```powershell
dotnet publish PureRDP/PureRDP.csproj -c Release -r win-x64 --self-contained false -p:PublishSingleFile=true -p:PublishTrimmed=false -o outputs/2.0.0-independent-preview
```

离线 UI 回归检查（先构建应用的 Release 版本）：

```powershell
dotnet run --project Build/tests/UiDesign/UiDesign.csproj -c Release
```

编译、渲染和离线回归不等于真实 RDP 会话、高 DPI、多显示器或长时间运行验收。
